# 产品与技术决策记录

## D-001：产品形态

状态：已决定

主形态为 macOS 菜单栏小工具，辅形态为可选悬浮桌面便签。完整主窗口不是 MVP 核心。

原因：用户需要在工作中快速查看额度，而不是进入一个独立分析产品。

## D-002：桌面便签先于 WidgetKit

状态：已决定

MVP 使用 AppKit 无边框 Panel 实现悬浮便签。WidgetKit 放到后续版本。

原因：WidgetKit 更新频率由系统调度，不能保证准实时；悬浮 Panel 可共享应用实时状态并支持点击交互。

## D-003：无云后端

状态：已决定

MVP 不建设账号系统、Web API 或远程数据库。“后端”指本机采集、标准化、账本、通知和连接器运行时。

例外：连接器经用户授权后，可访问对应平台的 usage/quota 接口；价格表和版本兼容提示可使用只读静态资源。

## D-004：直接分发优先

状态：已决定

首发采用 Developer ID 签名、公证的 DMG，并支持 Homebrew Cask。Mac App Store 版后续评估。

原因：App Sandbox 对多个第三方工具目录的自动发现和只读访问限制较大。

## D-005：本地优先与内容零采集

状态：已决定

不采集提示词、回复正文、代码、diff、工具参数或附件。只采集数值 telemetry、时间、模型标识、匿名会话键和必要的连接器健康信息。

## D-006：可信度优先于连接器数量

状态：已决定

连接器只有在具备真实样本、契约测试和明确数据来源后才能标记为“支持”。未稳定的平台显示 Beta、实验性或研究中。

## D-007：多种单位不强行统一

状态：已决定

Token、积分、请求、百分比、人民币和美元分别保存与展示。仅当存在明确价格规则时计算 API 等效成本，并始终标记为估算。

## D-008：首批连接器顺序

状态：暂定，需真实样本验证

工程基线：Claude Code、Codex。国内优先：Qoder CLI、Qoder IDE、Qoder Work、WorkBuddy、CodeBuddy、千问办公。至少六个连接器达到发布质量后进入公开 Beta。

## D-009：适配器不支持远程任意代码

状态：已决定

MVP 适配器随应用编译发布。远程只允许下发签名的禁用开关、兼容版本范围、路径候选和声明式字段映射；不得下载执行脚本或动态库。

## D-010：项目更名为 Usagy

状态：已决定

项目正式从 `AIUsageMeter` 更名为 `Usagy`。新名称更简洁、易记，符合产品定位。所有文档、代码和配置中的旧名称将逐步迁移。

## D-010A：显示名暂定

状态：待定

产品显示名暂定为"AI 用量表"。品牌名、图标和英文名在视觉探索后锁定，不阻塞架构与原型开发。

## D-011：最低系统版本

状态：已决定

MVP 最低支持 macOS 14。首发必须支持 Apple Silicon；Intel 构建是否发布取决于 Beta 设备覆盖，但代码不得主动依赖 Apple Silicon 专属能力。

## D-012：视觉系统

状态：已决定

AI 用量表继承 1Cash 与 Footy 已落地的 Swiss Ledger：Archivo、纸白/近黑、发丝描边、2 pt 方角、直角进度、等宽数字、无胶囊、无内容阴影、无玻璃材质。此前设计稿中的 SF Pro、10–14 pt 圆角、系统 material 和额度圆环全部废止。

强调色继续使用 Swiss Ledger 印刷红：浅色 `#C4321F`、深色 `#E2503A`，与 1Cash 保持一致。状态色继续使用 Swiss Ledger 的 success/warning/danger，不采用 Provider 品牌色系统。
